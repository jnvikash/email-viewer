# Email Viewer — .msg File Browser

A local Python web application for browsing, searching, and viewing Microsoft Outlook `.msg` files with a clean 3-pane interface inspired by Maemon webmail.

## Features

- **Dual Format Support**: Handles both binary OLE2 `.msg` files (Outlook) and RFC 822 MIME `.msg`/`.eml` files
- **3-Pane Layout**: Folder tree (left) | Email list (middle) | Reading pane (right)
- **Full-Text Search**: Search across subject, sender, body, and attachment text with FTS5
- **Folder Navigation**: Browse nested folder structures from your email archive
- **Sorting & Filtering**: Sort by date/sender/subject; filter by date range
- **Attachment Handling**: Preview images/PDFs inline, download any file
- **Background Indexing**: Automatic SQLite + FTS5 index on first run for fast searches
- **Simple Authentication**: Password-protected access (single user)
- **Large Volume Ready**: Handles thousands of .msg files efficiently

## File Format Support

The app automatically detects and handles two email message formats:

### OLE2 Structured Storage (.msg)
- Binary format used by Microsoft Outlook
- Contains embedded objects and complex structures
- Parsed via `extract-msg` library

### RFC 822 MIME (.msg, .eml, .txt)
- Text-based email format with headers and MIME parts
- Generated by email servers, MDaemon, and other mail systems
- Parsed via Python's built-in `email` library
- Supports multipart messages (text + HTML + attachments)

**Automatic Detection**: The app checks the file's magic bytes and attempts OLE2 parsing first, then falls back to MIME parsing if needed. Files that don't match either format are skipped with a debug log.

### Setup

1. **Clone or download the project**
   ```bash
   cd email-viewer
   ```

2. **Create virtual environment**
   ```bash
   python3 -m venv venv
   source venv/bin/activate  # On Windows: venv\Scripts\activate
   ```

3. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

## Usage

### First Run

1. **Start the app**
   ```bash
   python run.py
   ```
   The app runs on `http://localhost:5000`

2. **Set your password**
   - Open your browser to http://localhost:5000
   - Create a password (first-run only)
   - Sign in

3. **Configure email folder**
   - Go to Settings (⚙️)
   - Enter the absolute path to your .msg files folder
   - Click "Save Path"
   - Click "Start Indexing"
   - Wait for indexing to complete (progress shown in modal)

4. **Browse emails**
   - Once indexing is done, the folder tree will populate
   - Click folders to view emails
   - Click an email to read its full content
   - Use search bar to find emails across all folders

### Subsequent Runs

```bash
python run.py
```

Just sign in and browse. The index persists in `data/email_index.db`.

## Database

### Schema

- **emails**: Core email metadata (subject, sender, date, paths, etc.)
- **attachments**: Attachment list per email (filename, size, MIME type)
- **emails_fts**: FTS5 virtual table for full-text search (indexed at startup)
- **fts_body**: Email body text storage (synced with FTS5)
- **index_state**: Indexing progress and status

### Storage

- **Location**: `data/email_index.db`
- **Mode**: WAL (Write-Ahead Logging) for concurrent reads during indexing
- **Indexed**: All .msg files from root folder recursively on first run
- **Re-indexing**: Manual reset available in Settings; scans for new/updated files

## API Endpoints

| Method | Route | Purpose |
|--------|-------|---------|
| GET/POST | `/api/config` | Get/set root folder path & password |
| GET | `/api/folders` | Nested folder tree with email counts |
| GET | `/api/emails` | Paginated email list with sort/filter |
| GET | `/api/emails/<id>` | Full email detail + attachments |
| GET | `/api/attachments/<id>/<idx>/download` | Download attachment |
| GET | `/api/attachments/<id>/<idx>/preview` | Preview attachment inline |
| GET | `/api/search` | Full-text search with snippets |
| POST | `/api/index/start` | Start background indexing |
| GET | `/api/index/status` | Current indexing status |
| GET | `/api/index/progress` | SSE stream for progress bar |
| DELETE | `/api/index/reset` | Wipe index and re-index from scratch |

## Security

- ✅ **Local-only**: Bound to `127.0.0.1`, not accessible from network
- ✅ **Password-protected**: PBKDF2-SHA256 hashing via werkzeug
- ✅ **Session-based**: Secure session cookies (`SameSite=Lax`, `HttpOnly`)
- ✅ **HTML sanitized**: All email bodies cleaned with bleach allowlist before iframe rendering
- ✅ **No external resources**: External images/scripts stripped from emails
- ✅ **Safe attachment handling**: Files streamed from memory, no temp files on disk; attachment IDs resolved from DB only (no path traversal)

## Performance Tips

- **Large folders**: First indexing may take several minutes (5000 files ≈ 5–10 min). Use Settings to monitor progress.
- **Search**: FTS5 search typically completes in under 200ms after index is built.
- **Pagination**: Default 50 emails per page; adjust in Settings if needed.
- **Browser**: Works best in modern browsers (Chrome, Firefox, Safari, Edge).

## Troubleshooting

### "No emails found" after indexing
- Check the root folder path is correct and contains .msg files
- Verify file permissions allow read access
- Check `index_state` table via SQLite if folder is not found

### Login page loops
- Password is case-sensitive
- On first run, any password sets the initial one
- To reset: delete `settings.json` and restart

### Indexing is very slow
- Large .msg files or many attachments slow extraction
- Text extraction from PDFs/Office docs takes time
- Consider indexing during off-hours

### Memory usage
- Attachment text extraction is buffered; large attachments may peak memory
- SQLite WAL mode handles concurrent access efficiently
- Browser sessions consume minimal memory
